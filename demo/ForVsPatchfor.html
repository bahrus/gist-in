Verified 2026-09-13 against Chrome Canary 155.0.8055.0 with that flag: only for patches — patchfor (the name the flag's own description text uses) does nothing. The flag description is stale relative to the shipped behavior; the Chrome article's own examples (which use for) are the ones that match reality.

Also verified separately (not shown on this page): the native patch fires once, synchronously, at parse time. A <template for="x"></template> left empty at parse time and filled in later via script/fetch does not get a second chance — the template is already consumed and removed by the time anything async could populate it. That's the real reason gist-in can't just hand this off to the platform: gist-in's whole job is patching in content that arrives after parse time (a fetched gist), which is exactly the case this native mechanism doesn't cover yet.
